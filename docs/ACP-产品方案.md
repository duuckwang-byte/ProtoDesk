# PlanD ACP 接入 · 产品方案

> 版本：v0.1  
> 日期：2026-11-11  
> 范围：把现有「本地 CLI 一次性 spawn + stdout 解析」升级为「ACP 标准 Agent 运行时」，先覆盖 ACP 原生 Agent 与 Claude/Codex/Pi 适配器，非 ACP CLI 保留兼容模式。  
> 关联技术方案：`docs/ACP-技术方案.md`

---

## 1. 背景与问题

PlanD 现在通过 `runtimes/` 适配 26 个本地 Agent CLI，工作方式是：

```text
用户发送需求
  → 主进程解析可执行文件
  → 按每家 CLI 拼参数、spawn 一个进程
  → 解析 stdout / stream-json / 自定义事件
  → 把 thinking / chunk / tool_call / done 转成 ai:event
  → 前端渲染气泡、工具卡、日志
```

这套方式有三个结构性问题：

1. **每家 CLI 一套参数和解析器**：新增一个 CLI 要写 `buildArgs`、`streamFormat`、`parser`，维护成本高。
2. **权限是黑盒**：当前多数 CLI 用 `--yolo` / `--dangerously-skip-permissions` / `--allow-all-tools` 全放行，用户看不到 Agent 要执行什么，也无法逐条审批。
3. **会话和交互能力弱**：会话 ID 只是字符串透传，恢复不可靠；工具调用、计划、终端、文件变更、用量等只能是「尽量解析」，不是协议保证。

ACP（Agent Client Protocol）解决的正是这三个问题：JSON-RPC 结构化通信、标准会话生命周期、标准权限请求、标准工具/计划/终端/文件能力。

## 2. 产品目标与非目标

### 2.1 目标

| 目标 | 说明 |
|---|---|
| 统一 Agent 接入 | ACP 原生 Agent 直接接入；Claude / Codex / Pi 通过官方适配器接入 |
| 权限可见可控 | 读操作默认放行，写文件 / 执行命令 / 网络访问逐条询问 |
| 会话可恢复 | 重开对话框、重启应用后可恢复上次 ACP 会话（Agent 支持时） |
| 输出结构化 | 思考、正文、工具调用、计划、终端、文件变更、用量都有标准事件 |
| 兼容不破坏 | 非 ACP CLI 继续走现有兼容模式，用户无感 |
| 可诊断 | 提供 ACP 连接测试、能力查看、JSON-RPC 流量日志 |

### 2.2 非目标

- 不替换「API 直连」模式；API 模式继续走现有 OpenCode BYOK 链路。
- 不删除任何现有 CLI 适配器；非 ACP CLI 保留兼容模式。
- 不做独立 AI 会话窗口；AI 对话统一在工具内 `#aiMask` 弹窗完成。
- 不在本期实现「Agent 市场 / 一键安装全部 Agent」。
- 不把 ACP 权限审批宣传成操作系统沙箱；它仍是应用层策略。
- 不做云端会话同步；会话数据只存本机。

## 3. 核心用户场景

### 场景 A：首次使用 ACP Agent

1. 用户打开设置 → Agent 设置。
2. 系统显示本机已安装 Agent，并标记「ACP 可用 / 需适配器 / 仅兼容模式」。
3. 用户选择一个 Agent，点击「测试连接」。
4. 若需要登录，出现「登录 / 配置凭据」卡片；若需要适配器，出现「安装适配器」卡片。
5. 连接成功后，卡片显示「ACP 已连接」和能力标签（会话恢复 / 权限 / 终端 / 文件 / MCP）。

### 场景 B：日常修改原型

1. 用户在预览中拾取元素，写修改需求，点击发送。
2. 对话框顶部显示「正在连接 Agent」→「等待响应」。
3. Agent 开始输出思考、正文、工具调用。
4. 当 Agent 要写文件或执行命令时，聊天流中出现权限卡片：
   - 操作类型：写文件 / 执行命令 / 网络请求
   - 具体目标：文件路径 / 命令行 / URL
   - 选项：允许一次 / 本会话始终允许 / 拒绝
5. 用户选择后，Agent 继续执行；完成后自动刷新预览，生成快照和文件变更卡。

### 场景 C：长任务与工具内 AI 弹窗

1. 用户点击「AI设计」或提交待提交列表，工具内打开 AI 对话弹窗。
2. 任务在弹窗内运行；关闭弹窗不中断后台任务。
3. 需要授权时，AI 弹窗内出现权限卡，弹窗入口显示待处理状态。
4. 用户处理权限后任务继续；任务进行中可随时点击停止。重新打开弹窗可续接当前会话与流式输出。

### 场景 D：会话恢复

1. 用户重新打开某个原型的 AI 对话弹窗。
2. 若上次 ACP 会话仍可恢复，显示「已恢复上次会话」。
3. 若 Agent 不支持恢复，显示「该 Agent 不支持恢复，已开启新会话」，本地历史仍保留。
4. 用户可继续对话，上下文按 Agent 能力恢复。

### 场景 E：切换 Agent

1. 用户在对话框顶部点击 Agent 徽标，选择另一个 Agent。
2. 系统提示：「切换 Agent 将开启新会话，是否带入最近 20 条对话摘要？」
3. 确认后，旧会话保留在会话列表；新 Agent 建立新 ACP 会话。
4. 新会话首条消息附带摘要，避免上下文完全丢失。

## 4. 要接入的 ACP 能力

### 4.1 能力清单与优先级

| 能力 | 说明 | 优先级 | 用户可见变化 |
|---|---|---|---|
| ACP 初始化 | `initialize` 协商协议版本与客户端能力 | P0 |  Agent 卡片显示「可连接 / 协议版本」 |
| 会话新建 | `session/new` 创建会话 | P0 | 新对话可用；会话 ID 落盘 |
| 会话恢复 | `session/load` 或 `session/resume` | P1 | 重开对话框可续接 |
| Prompt 轮次 | `session/prompt` + `session/update` | P0 | 流式输出 |
| 思考/正文 | `agent_thought_chunk` / `agent_message_chunk` | P0 | 思考链、正文气泡 |
| 工具调用 | `tool_call` / `tool_call_update` | P0 | 工具卡、命令/路径、状态 |
| 权限请求 | `session/request_permission` | P0 | 权限卡片、允许/拒绝 |
| 取消 | `session/cancel` | P0 | 停止生成更可靠 |
| 问题/表单 | `elicitation/create` | P1 | 原生提问卡（radio/text） |
| 计划 | `plan` 更新 | P1 | 任务计划/待办卡 |
| 文件变更 | 工具调用中的 diff / 文件内容 | P1 | 文件变更卡实时更新 |
| 终端 | `terminal/create` / `output` / `kill` | P1 | 工具卡内终端输出 |
| 模型/模式 | `session/set_model`、`set_mode`、`set_config_option` | P1 | 模型/模式/推理强度选择器 |
| 用量/成本 | `usage_update`、prompt 结果 | P1 | 用量卡、日志用量行 |
| 认证 | `authenticate` | P1 | 登录卡、凭据配置 |
| MCP | `session/new` 的 `mcpServers` | P2 | 把 PlanD 工具暴露给 Agent |
| 附件 | 图片/文件附件 | P2 | 对话框支持粘贴图片 |
| 多会话并发 | 多个 ACP 会话同时运行 | P2 | 多任务并行 |
| Agent 接力 | 切换 Agent 时携带摘要 | P2 | 跨 Agent 继续任务 |

### 4.2 不在 P0 的能力

- 会话恢复、问题表单、计划、终端、模型/模式切换放到 P1。
- MCP、附件、多会话并发、Agent 接力放到 P2。
- 这样 P0 只做「能连、能跑、能审批、能停止」，风险最小。

## 5. 页面与功能改动

### 5.0 改动总览

| 页面 / 模块 | 改动级别 | 主要变化 |
|---|---|---|
| 设置 → Agent 设置 | 大改 | ACP 状态、能力标签、适配器区块、权限默认值、连接诊断 |
| 设置 → 模型管理 | 中改 | Agent 声明模型、模式、推理强度、来源标签 |
| 设置 → 沙箱 | 中改 | Agent 工作区、能力开关、权限超时、会话清理 |
| AI 对话弹窗（工具内） | 大改 | 作为唯一 AI 会话界面；ACP 状态、权限卡、问题卡、计划卡、终端卡、用量卡、模型/模式 |
| AI 会话窗口（独立） | 删除 | 不再创建独立 BrowserWindow；入口统一打开工具内弹窗 |
| 执行日志 Trace | 中改 | 事件 / 协议 / 原始三视图、JSON-RPC 过滤与导出 |
| 顶部工具栏 | 小改 | Agent 状态胶囊、终端语义说明 |
| 新建原型 / 首次引导 | 中改 | 选择 Agent、安装/登录引导、兼容模式入口 |
| 原型列表 | 小改 | 运行中 / 等待授权 / 失败徽标 |
| 快照历史 | 小改 | Agent、传输方式、停止原因、用量元信息 |
| 待提交 / 拾取条 | 小改 | 权限摘要、范围确认保留 |
| 终端 | 小改 | ACP-only Agent 的禁用提示；Agent 终端输出进聊天流 |

### 5.1 设置 → Agent 设置

**现状**

- 26 张 Agent 卡片，已安装/未安装分组。
- 卡片只显示名称、路径、状态点、「指定路径」。
- 点击卡片设为「主力 Agent」。
- 没有 ACP 连接状态、能力、权限策略、适配器概念。

**改成**

1. 顶部增加筛选：
   - 全部
   - 已安装
   - ACP 可用
   - 需要适配器
   - 仅兼容模式
2. 卡片增加：
   - 传输徽标：`ACP` / `兼容`
   - 连接状态：`未检测` / `可连接` / `需登录` / `已连接` / `连接失败`
   - 版本、路径
   - 能力标签：`会话恢复` `权限` `终端` `文件` `MCP`
   - 操作：`设为默认` `测试连接` `指定路径` `更多`
3. 增加「ACP 适配器」区块：
   - Claude Code → `claude-agent-acp`
   - Codex → `codex-acp`
   - Pi → `pi-acp`
   - 显示「已安装 / 未安装 / 版本」，提供安装指引或一键安装（P1）。
4. 增加「权限默认值」：
   - 只读
   - 按需审批（推荐）
   - 自动放行
   - 高级：按工具类型配置（读/写/执行/网络）
5. 增加「连接诊断」：
   - 测试连接
   - 查看能力
   - 查看 ACP 会话
   - 打开 JSON-RPC 日志

**交互**

- 点击卡片仍然设为默认 Agent，但只有在「ACP 已连接」或「兼容可用」时才允许发送任务。
- 点击「测试连接」才发起 ACP `initialize`，不在 26 个 Agent 的列表探测阶段逐个握手。
- 连接失败时卡片内展示原因和「查看日志 / 重试 / 切换兼容模式」。

### 5.2 设置 → 模型管理

**现状**

- 按 API / CLI 分开拉取模型。
- CLI 模型来自静态 fallback + `listModels` 命令 + 用户自定义。
- 没有「模式」概念，推理强度是独立下拉。

**改成**

1. 模型列表增加来源标签：
   - `Agent 声明`
   - `静态兜底`
   - `手动添加`
2. 增加「模式」分组：
   - 例如 `Plan` / `Ask` / `Agent` / `Read-only`
   - 由 ACP `configOptions` 或 `session/set_mode` 提供
3. 增加「推理强度」：
   - 若 Agent 通过 `configOptions` 声明，合并进现有级联选择器。
4. 增加「从 Agent 刷新」：
   - 调用 `inspectAgentModels` 或会话 `getStatus`，带 10 分钟缓存。
5. 如果 Agent 不支持模型选择：
   - 显示「由 Agent 配置决定」，禁用选择器，不再展示错误的静态模型。

### 5.3 设置 → 沙箱

**现状**

- 只显示沙箱根目录、项目加载模式。

**改成**

1. 增加「Agent 工作区」：
   - 当前原型沙箱目录（只读展示）
   - 允许 Agent 访问的附加目录（P1）
2. 增加「能力开关」：
   - 允许文件读取（默认开）
   - 允许文件写入（默认开，受权限审批）
   - 允许终端（默认开，受权限审批）
   - 允许网络（默认关，P1）
   - 说明：MVP 阶段文件/终端能力是运行时级开关，由权限策略逐条约束；按 Agent 精细开关放到 P1。
3. 增加「权限超时」：
   - 默认 120 秒；超时按拒绝处理。
4. 增加「会话数据」：
   - 存储位置
   - 清理本机 ACP 会话
   - 导出诊断日志

### 5.4 AI 对话弹窗（工具内）

**现状**

- 主工具窗口内 `#aiMask` 弹窗承载 AI 会话，不创建独立 BrowserWindow。
- 顶部：需求对话 / 执行日志、历史、沙箱、CLI 状态、Agent 徽标。
- 左侧：会话列表。
- 中间：气泡 + 思考 + 工具卡 + 文件变更 + 快照卡 + 错误卡。
- 底部：输入框、作用页面、模型级联、清空、发送/停止。

**改成**

1. 顶部状态区：
   - Agent 徽标可点击，弹出快速切换。
   - 增加 ACP 状态：`连接中` / `已连接` / `等待授权` / `已断开`。
   - 增加权限模式徽标：`只读` / `按需审批` / `自动放行`。
   - 会话状态：`新会话` / `已恢复` / `运行中` / `等待授权`。
2. 聊天流新增卡片：
   - **权限请求卡**：操作类型、目标、风险、允许一次/本会话始终允许/拒绝。
   - **问题卡**：Agent 提问，radio/text，必填校验，推荐项。
   - **计划卡**：ACP plan，显示 pending / in_progress / completed。
   - **终端输出卡**：命令、实时输出、退出码、停止按钮。
   - **用量卡**：token 输入/输出/缓存、成本（若 Agent 提供）。
   - **连接状态卡**：连接中、已断开、正在重连、认证失败。
3. 工具卡增强：
   - 显示工具类型图标（读/写/执行/搜索/网络）。
   - 显示命令、路径、状态、耗时。
   - 文件变更直接嵌在工具卡内，保留现有文件变更汇总卡。
4. 底部：
   - 模型级联增加「模式」和「推理强度」。
   - 增加权限模式快捷切换（只读 / 按需 / 自动）。
   - 发送 / 停止保持现有行为；停止优先走 ACP `session/cancel`，超时才杀进程。
5. 会话列表：
   - 每个会话显示 Agent 名称、状态、最后活动时间。
   - 支持「恢复」「重命名」「删除」。
   - 当前会话显示 ACP 会话 ID（可复制，便于排查）。

### 5.5 AI 弹窗生命周期

**现状**

- 工具内弹窗复用同一套 AI UI；关闭弹窗不结束后台任务。
- 「AI设计」、新建原型、待提交列表都打开工具内弹窗。
- 重新打开弹窗时按当前沙箱/会话续接历史与流式输出。

**改成**

1. 会话状态由主进程统一维护；工具内弹窗是唯一 AI 会话界面。
2. 权限请求、问题卡只在弹窗内展示；入口可显示待授权数量。
3. 关闭弹窗时任务继续后台运行；停止任务通过弹窗内「停止生成」完成。
4. 弹窗内可查看 ACP 连接状态和诊断日志。
5. 不再创建独立 AI 窗口，也不存在关窗转移/续跑兼容路径。

### 5.6 执行日志（Trace）

**现状**

- 按任务分组的思考/操作/删除/输出日志。
- 支持复制、清空、全部展开、自动吸底。

**改成**

1. 增加视图切换：
   - `事件`：用户可读的任务事件（现有）
   - `协议`：ACP JSON-RPC 请求/响应/通知
   - `原始`：Agent 原始输出（兼容模式）
2. 协议视图显示：
   - 方向（→ / ←）
   - 方法名（`session/prompt`、`session/update`、`session/request_permission`）
   - 请求 ID、耗时、错误码
   - 敏感字段脱敏
3. 支持按方法名过滤、复制单条、导出诊断包。
4. 协议视图默认关闭，设置中可开启「记录 ACP 协议流量」。

### 5.7 顶部工具栏

**现状**

- 项目、端别、缩放、交互、标注、刷新、Git、终端、导出、待提交。

**改成**

1. 增加 Agent 状态胶囊：
   - `Agent: OpenCode · ACP`
   - 运行中显示旋转点；等待授权显示橙色点。
2. 「终端」按钮保持原义：打开当前沙箱的用户终端。
3. Agent 终端输出不占用顶部「终端」，而是出现在聊天流的终端卡 / Trace 协议视图。
4. 若当前 Agent 是 ACP 专属、无交互终端（如 Vibe），终端按钮显示禁用提示。

### 5.8 新建原型 / 首次引导

**现状**

- 新建原型先选 PC/移动，创建空 HTML + MD，然后自动打开工具内 AI 对话弹窗。

**改成**

1. 创建后增加「选择 Agent」步骤（可跳过，使用默认 Agent）。
2. 首次使用且没有可用 ACP Agent 时，展示引导：
   - 检测本机已安装 Agent
   - 推荐安装/启用一个 ACP Agent
   - 提供「先用兼容模式」入口
3. 不阻塞只想预览原型的用户。

### 5.9 原型列表

**现状**

- 仅显示原型名称、子页面、会话状态。

**改成**

1. 原型项增加小徽标：
   - Agent 运行中
   - 等待授权
   - 最近任务失败
2. 悬浮提示显示当前 Agent、会话状态、最后活动时间。
3. 点击徽标可直接打开对应会话。

### 5.10 快照历史

**现状**

- 每次 AI 任务前自动快照，支持恢复。

**改成**

1. 快照条目增加元信息：
   - Agent 名称
   - 传输方式（ACP / 兼容）
   - 停止原因（完成 / 取消 / 权限拒绝 / 错误）
   - token 用量
2. 恢复逻辑不变；恢复前仍二次确认。

### 5.11 待提交 / 拾取条

**现状**

- 拾取元素后写需求，加入待提交列表，统一提交给 AI。

**改成**

1. 提交前显示「本次任务权限摘要」：
   - 预计只读 / 可能写文件 / 可能执行命令
   - 当前权限模式
2. 若检测到沙箱外引用，保留现有「范围确认」弹窗。
3. 权限审批仍在任务运行中逐条出现，不在提交前一次性全放行。

### 5.12 不变的部分

以下功能保持现有交互，不在本期改动：

- 原型预览、缩放、移动/PC 端别切换
- 文档编辑、搜索、导出（PNG / PDF / MD）
- 元素拾取、批量修改、元素检查器
- 标注、跳转绑定、待提交列表
- Git 上传发布 / 拉取同步 / 仓库设置
- 快照备份与恢复
- 导出原型源码 / 导出 HTML
- API 直连模式（BYOK）
- 用户终端（顶层「终端」按钮）

## 6. 交互变化详解

### 6.1 发送任务

**现在**

```text
点击发送 → 进入忙态 → spawn CLI → 等待输出 → 完成
```

**之后**

```text
点击发送
  → 预检：沙箱范围 / 权限模式
  → 连接 Agent（首次约 1-3 秒）
  → 创建/恢复会话
  → 发送 prompt
  → 流式输出
  → 遇到权限请求：暂停并显示卡片
  → 用户允许/拒绝
  → 继续输出
  → 完成：刷新预览、快照、文件变更
```

用户感知变化：

- 首次发送多一个「连接 Agent」状态，后续会话复用连接，几乎无感。
- 任务可能停在「等待授权」，这是预期行为，不是卡死。
- 停止按钮更可靠，优先协议取消，超时才杀进程。

### 6.2 权限请求

**卡片内容**

```text
Agent 请求执行操作
[执行命令]  npm run build
目录：D:\...\sandbox\项目A
风险：会修改工作区文件

[拒绝]  [本会话始终允许此类]  [允许一次]
```

**规则**

- 读 / 搜索：默认自动允许，不打断。
- 写文件 / 执行命令 / 网络：默认逐条询问。
- 「本会话始终允许此类」只对当前会话、当前工具类型生效。
- 用户拒绝后，Agent 可以选择换一种方式或结束；UI 不强制失败。
- 120 秒无响应按拒绝处理，任务继续或结束，并记录日志。
- 权限请求不弹全屏模态，避免遮挡对话；用内联卡片 + 顶部「待处理」角标。
- 若窗口不在前台，任务栏/标题显示待处理数量。

### 6.3 问题 / 表单

- Agent 通过 ACP `elicitation/create` 提问时，复用现有 `question-form` 卡片样式。
- 支持 radio / text；推荐项默认选中；必填校验。
- 回答后任务继续；不回答则任务等待，超时按取消处理。
- 兼容模式下仍保留现有「从助手文本解析 question-form」的能力。

### 6.4 会话恢复

- 打开对话框时，先读本地会话记录，再尝试 ACP 恢复。
- 恢复成功：显示「已恢复」+ 最后活动时间。
- 恢复失败：
  - Agent 不支持：静默开新会话，提示一次。
  - 会话过期：开新会话，保留本地历史。
  - Agent 崩溃：显示「重新连接」按钮。
- 用户点「清空」：关闭旧 ACP 会话，开新会话；本地消息清空。

### 6.5 切换 Agent

- 切换 Agent 必须新开会话，因为 ACP 会话绑定 Agent。
- 切换时弹确认：
  - 「仅切换，不带上下文」
  - 「切换并带入最近 20 条摘要」
  - 「取消」
- 旧会话保留在会话列表，可随时切回。
- 新 Agent 的首条消息可带摘要，避免从零开始。

### 6.6 模型 / 模式切换

- 模型选择器优先展示 Agent 声明的模型。
- 若 Agent 声明了模式（Plan / Ask / Agent），在模型选择器上方显示模式切换。
- 若 Agent 不支持切换，显示「由 Agent 配置决定」，不展示假选项。
- 切换模型/模式在下一轮生效；当前轮次进行中禁用并提示。

### 6.7 取消 / 失败

- 用户点「停止生成」：
  1. 发送 ACP `session/cancel`。
  2. 等待 2 秒。
  3. 未结束则杀进程树。
  4. UI 显示「已停止」，不显示红色错误卡。
- 权限拒绝导致任务结束：显示黄色提示卡，不是红色错误。
- 连接失败：
  - 适配器缺失 → 「安装适配器」
  - 需要登录 → 「登录 / 配置凭据」
  - 协议不支持 → 「切换兼容模式」
  - Agent 崩溃 → 「重新连接 / 重试」

### 6.8 窗口关系

- 主工具窗口内 `#aiMask` 弹窗是唯一 AI 界面；权限/问题卡在该弹窗内展示。
- 「AI设计」、新建原型、待提交列表都打开工具内弹窗，不再创建独立 AI 窗口。
- 关闭 AI 弹窗不结束任务；任务在后台继续，重新打开弹窗可续接当前会话。
- 主窗口关闭时按应用退出处理，正在跑的任务随进程结束。

## 7. 权限与安全策略

### 7.1 三档默认策略

| 模式 | 行为 | 适用用户 |
|---|---|---|
| 只读 | 读/搜索自动允许；写/执行/网络一律拒绝 | 审查、看代码、生成建议 |
| 按需审批（推荐） | 读/搜索自动允许；写/执行/网络逐条询问 | 日常原型修改 |
| 自动放行 | 除明确拒绝规则外全部允许 | 信任的本地项目、批量任务 |

### 7.2 权限卡片必须展示

- 工具类型（读 / 写 / 执行 / 搜索 / 网络）
- 具体目标（文件路径 / 命令行 / URL）
- 工作目录
- 是否超出沙箱
- 风险提示（如「会删除文件」「会执行 shell」）
- 选项：允许一次 / 本会话始终允许此类 / 拒绝

### 7.3 安全边界

- ACP 的 `fs/*` 走 acpx 的文件系统守卫，限制在会话 cwd 内。
- 现有「沙箱根越界守卫」保留，任务前后对比变更。
- 现有「范围确认」保留，检测提示词中的沙箱外路径。
- ACP 权限审批不是 OS 沙箱；设置页明确提示。
- 所有权限决定写入本地审计日志（时间、Agent、工具、目标、决定）。

## 8. 状态与文案

### 8.1 Agent 状态

| 状态 | 文案 | 颜色 |
|---|---|---|
| `missing` | 未安装 | 灰 |
| `available` | 已安装 | 绿 |
| `acp_ready` | ACP 可连接 | 蓝 |
| `auth_required` | 需要登录 | 橙 |
| `connected` | 已连接 | 绿 |
| `error` | 连接失败 | 红 |
| `legacy_only` | 仅兼容模式 | 灰蓝 |

### 8.2 会话状态

| 状态 | 文案 |
|---|---|
| `new` | 新会话 |
| `restored` | 已恢复上次会话 |
| `running` | 运行中 |
| `waiting_permission` | 等待授权 |
| `waiting_answer` | 等待回答 |
| `cancelled` | 已停止 |
| `failed` | 执行失败 |
| `disconnected` | 连接已断开 |

### 8.3 错误文案原则

- 说清楚「发生了什么」+「用户能做什么」。
- 不暴露 JSON-RPC 原始错误给普通用户；放在「详情 / 协议日志」。
- 适配器缺失、需要登录、权限拒绝、协议不支持，分别给不同行动按钮。

## 9. 兼容与迁移

### 9.1 双通道

- 每个 Agent 增加 `transport` 配置：
  - `acp`：只走 ACP
  - `legacy`：只走现有 CLI
  - `auto`：优先 ACP，失败自动回退 legacy（默认）
- UI 用徽标明确标识当前通道，避免用户误以为所有 Agent 都走 ACP。

### 9.2 迁移策略

1. 先接 3 个：OpenCode、Claude Code、Codex。
2. 再扩到所有 ACP 原生 Agent。
3. 非 ACP Agent 保持 legacy，不强行迁移。
4. 适配器（Claude/Codex/Pi）优先检测已安装版本；未安装时给安装引导，不默认走 `npx` 联网。

### 9.3 回滚

- 设置中可把某个 Agent 切回 `legacy`。
- 全局开关 `acp.enabled=false` 可一键回到旧链路。
- 会话数据不回写旧格式；旧会话仍可读，新 ACP 会话独立存储。

## 11. 风险与依赖

| 风险 | 影响 | 应对 |
|---|---|---|
| acpx 仍是 pre-1.0 | API 可能变 | 锁定版本、封装适配层、必要时 vendor |
| Electron 37 升级回归 | 影响现有窗口/iframe/DevTools | 已升级 37.10.3 并跑 52 项测试；继续做安装包冷启动回归，保留 33 回滚分支 |

| Agent 认证方式不一 | 部分 Agent 不可用 | P1 做登录引导；先覆盖无需登录的 Agent |
| 权限请求打扰 | 用户烦 | 读操作自动放行、会话级记住、风险分级 |
